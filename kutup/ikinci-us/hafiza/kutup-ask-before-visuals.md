Batur said on 16 Oct 2026, mid-n16: if a package's decisions aren't all settled, or you aren't sure about the visual style or what he wants, ask him questions — ideally with visual previews (screenshots/mockups of the real site) — and get it right before shipping. Every new session must first look at the site's existing style (open the preview, screenshot the screens the work touches), because sessions keep changing and visual mismatches slip in. A session that writes a task brief for another must spell out the details (look, placement, copy, states, what's decided vs open).

**Why:** Work moves to a fresh session per package ([[kutup-work-mode]]), so taste context gets lost; the n13 avatars were rejected for clashing with the site ("siteyle alakası yok").

**How to apply:** Overrides the old "don't ask, decide yourself" default for visual/taste choices only; still no question storms for technical choices. Read kutup/DESIGN.md first (colors, type, Kara's drawing language, approved vs rejected looks in §9); add a §9 line after every visual decision. Start each visual package by screenshotting the affected screens; build a quick preview in the real app (light + dark, 375px) and ask one or two option questions with the images before deploying. When queuing or handing off a package, write a detailed brief on the board/HANDOFF. See [[kutup-work-board]], [[kutup-ios-first]].

Calibration (n06, 16 Oct 2026): approval is needed on the *look* (a still sheet of the drawing, big + in place, light + dark). Once he approves it and says "uygula", he may want it live without preview videos ("direkt deploy, videoya gerek yok ben bakarım canlıdan"); don't spend a long round on videos after the look is approved. He also redirects mid-work with reference images; drop drafts he hasn't seen and follow the reference.
